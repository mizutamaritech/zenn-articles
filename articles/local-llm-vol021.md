## 前回のあらすじ

プライバシーが欲しくて、手元のMacにプライバシーLLMを作っている。

macOSの「別ユーザー」で別室を作り、
部屋の中にAI本体を組み立てて、改造できないように固めた。

受付には「部屋の中身の手本」を持たせて、
主が来るたびに、部品がすり替えられていないか照らし合わせる。

今回は、AIの記憶をしまう**金庫**を作る話です。

## 金庫を作った

AIの記憶や会話は、必ず**金庫**にしまう。

金庫の正体は、パスワード付きの暗号化したディスクイメージです。

- パスワードは、どこにも保存しない
- 主が来るたびに、毎回入力する
- 閉めている間は、中身はただの暗号の塊

部屋の中には、金庫のほかに2つの場所を用意しました。

| 場所 | 役割 |
|---|---|
| 金庫 | 記憶や会話をしまう本体 |
| 窓口 | 金庫を開けた時だけ、中身が見える場所。閉めている時は空っぽで、立ち入り禁止 |
| 作業メモ置き場 | 金庫番の作業メモ（今使っているか、後片付けは済んだか） |

## 金庫の中身が、外に書き写されないか

金庫を閉めていても、Macのどこかに中身の写しがあったら意味がありません。

気になったのは2つ。

- Macの**検索機能**が、金庫の中を目録にしていないか
- **バックアップ**に、金庫がコピーされないか

### 検索機能：表示は「分からない」

検索の目録をオフにして、状態を確かめると。

**「状態が分からない（unknown）」**

何度やっても、分からない。
表示を出さない設定を外しても、分からない。

……オフになったのか、なっていないのか。

ここで、表示を信じるのはやめました。
**目録の設定ファイルと、目録そのものを直接見る**ことにします。

- 設定ファイルには「中身の目録は作らない」と書かれていて、更新時刻はオフにした瞬間
- 目録の置き場は、空っぽ
- 目印のファイルを置いても、目録は更新されない
- **金庫の外の目録にも、目印の名前は載っていない**

表示は「分からない」でも、中身は「作っていない」でした。

しかも目録の置き場は、金庫の**内側**にある。
仮に目録が作られても、閉めれば一緒に暗号化されます。

### バックアップ：閉めると対象に戻っていた

金庫を開けている間は、自動でバックアップの対象外。
ところが閉めると、**窓口も金庫のファイルも、対象に戻っていた**。

今はバックアップ先が無いので実害はなし。
でも将来バックアップを始めた瞬間、暗号化された金庫が外にコピーされるところでした。

管理人として、両方を対象外に固定しました。
部屋の住人には、この設定を外せません。

## 受付係、金庫番に昇格

受付係は、仕事が増えました。

主が来ると、

1. 使用中の印を取る
2. 前回の後片付けに失敗した印が無いか確かめる
3. 窓口の床に何も落ちていないか確かめる
4. **金庫のパスワードを聞いて、金庫を開ける**
5. AIを呼ぶ
6. 終わったら、**必ず金庫を閉める**

もう受付係ではありません。

**金庫番**です。

## 試験を9つ

金庫番が本当に「必ず閉める」のか。
試験をしました。

| 起こしたこと | 金庫番 |
|---|---|
| 普通に使う | 開けて、終わったら閉める |
| パスワードを間違える | 開けずに断る |
| 窓口の床に物を置いておく | パスワードを聞く前に「平文の疑い」で断る |
| 使用中にもう1人入ろうとする | 2人目を断る。1人目は邪魔しない |
| 後片付け失敗の印を置いておく | 確かめるまで使わせない |
| 使用中に金庫を無理やり外す | 一瞬でAIを止める |
| 途中で強制的に抜ける | 閉めて終わる |
| 回線を突然切る | 10秒以内に閉まって、誰も残らない |
| 作業メモを書けなくする | AIを止めて閉める |

どの試験の後も、

- 金庫は閉まっている
- 窓口は空っぽで、立ち入り禁止
- 作業メモは「使用中の印」だけ

金庫番、いい仕事をしてくれる。


## 金庫番が倒れたら？

ここで、ふと思いました。

**金庫番そのものが、突然倒れたら？**

金庫を開けたまま、誰も閉める人がいない。
床に何かが置かれても、気づく人がいない。

そこで、金庫番に**相棒の見張り役**を付けました。

- 見張り役が倒れたら → 金庫番がすぐ気づいて、AIを止めて金庫を閉める
- 金庫番が倒れたら → 見張り役が代わりにAIを止めて金庫を閉め、「何があったか」をメモに残す
- 次に主が来た時、そのメモを1回だけ見せる

### 試したつもりが、試せていなかった

金庫番を倒してみると、見張り役はちゃんと金庫を閉めて、メモを残しました。

でも、メモをよく見ると、
**「AIを止めた」という記録が無い。**

調べると、金庫番が倒れて回線が切れた瞬間、
AI役のプログラムが**回線切れの合図で、勝手に消えていた**のです。

見張り役が駆けつけた時には、止める相手がいなかった。

つまり「見張り役がAIを止める」部分は、試したつもりで、**試せていなかった。**

### おとり作戦

そこで、回線切れの合図を無視する**おとり**を用意しました。
AIと同じ目印を付けて、居残るプロセスです。

ところが、金庫番の探し方では、**おとりの目印が見えない。**

ここで一度止まって、切り分けました。

- 目印そのものは、ちゃんと付いている
- Apple製のプログラム（sleepやbash）は、目印が**0件**
- Apple製でないプログラム（部屋のpython）は、目印が**読める**

分かったのは、Macの仕組みでした。

**金庫番、見張り役の権限では、Apple製のプログラムの目印だけが読めない。**

本物のAIは部屋のpythonで動くので、目印は読めます。
おとりをpythonで作り直したら、見張り役は**おとりを止めて、金庫を閉め、メモにも「1件止めた」と残しました。**

ただ、AIが動かすApple製の道具が居残ったら、見つけられない。
これは次の段で解決する予定の宿題です。

## 両方同時に倒れたら？

最後の試験。

**金庫番と見張り役を、同時に倒す。**

これはさすがに、金庫が開いたまま残ります。
ここは割り切りました。

その代わり、次に主が来た時。
金庫番は**パスワードを聞く前に**、前回の残りを見つけて片付けてから始めます。

> 警告: 前回の残留を後始末しました: プロセス 1 件・マウント

そして、どの試験の前後でも、
**隣で動いている他のエージェント達は、一度も止まりませんでした。**

## 学んだこと

**表示を信じず、中身を見る。**
「分からない」と表示されても、中身を直接見れば「作っていない」と分かった。

**試験は「わざと崩す」が本番。**
通るかどうかより、崩した時に断るか・閉めるかを見る。

**倒した時の動きは、本当に倒さないと分からない。**
勝手に消えるAI役のせいで、試したつもりの部分が試せていなかった。

**想定外で止まると、前提が見つかる。**
目印が見えないところで止まって切り分けたら、Macの仕組みという大事な前提に出会えた。

そして、

**金庫番に相棒ができると、少し安心する。**

次回は、部屋の中にもう一枚**囲い**を作る話。
AIが動かす道具まで、まとめて見張れるようにします。
