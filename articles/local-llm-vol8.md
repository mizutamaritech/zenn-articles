でも実は、引っ越しと同時にもう一つやっていた。**Mac miniをネットワークから追放する**という作業だ。

家に迎え入れたばかりなのに追放とは何事だ、と思うかもしれない。でも理由がある。

---

## なぜ追放したかったか

AIのボットを動かすというのは、インターネットと常時繋がった「得体の知れない何か」を自宅のLANに住まわせるということだ。

冷静に考えると、それなりに怖い。

Discordトークンが漏れたら。ボットが暴走したら。何かの脆弱性を踏んだら。最悪、そこを踏み台にしてメインPCまで被害が及ぶ。

普段は意識しないが、**「同じLANにいる」というだけで、いざという時の被害範囲はぐっと広がる。**

だったら、最初から別の部屋に住まわせておけばいい。鍵は私だけが持っておく。そういう発想だ。

---

## 目指した構成

絵にするとこうなる。

```
インターネット
      │
  メインルーター（192.168.10.x）
  ├── メインPC
  ├── その他デバイス
  └── サブルーター（WANポートに接続）
            │
       サブルーター（RTモード）
       192.168.11.x ← 隔離部屋
       └── Mac mini M4（有線・固定IP）
                │
           Tailscale
           （暗号化トンネル）
                │
           メインPCからSSHで会いに行く
```

ルーターをもう1台足して、その奥にMac miniを置く。サブネットが別なので、普段はメインネットワークから姿が見えない。会いたいときだけTailscaleのトンネルを通って訪ねていく。

**「SSHだけ通す隔離ネットワーク」** という構成だ。素人の思いつきかと思ったら、わりと王道だった。

---

## 機器の選択：余り物で十分だった

サブルーターには手元で余っていたルーターを使った。RTモード（ルーターモード）で動かすと、別サブネットを作れる。

最初はブリッジモード（APモード）で繋ごうとした。が、それだとMac miniがメインと同じLANに見えてしまう。これでは「同じ部屋に布をかけて隠した」だけで、隔離になっていない。RTモードが必須だった。

---

## 詰まったこと3つ（毎度おなじみ）

### 1. 管理画面に繋がらない（自分とぶつかる）

サブルーターのLAN側IPが、メインルーターと同じ `192.168.10.1` だった。

つまり、家に表札が同じ住所の建物が2つある状態。ブラウザで管理画面を開こうとしても、どっちのルーターと話しているのかわからない。

解決策は、いったん**WANケーブルを抜いて孤立させてから設定する**こと。メインルーターと切り離した状態でサブルーターの管理画面に入り、LAN側IPを `192.168.11.1` に変更した。住所を変えたら、ようやく別の建物として認識された。

### 2. WSL2から「No route to host」が出る

Tailscaleを両方に入れて、満を持してSSH。

```
ssh: connect to host xxx.xxx.xxx.xxx port 22: No route to host
```

経路がない、と冷たく突き返された。

犯人はWSL2の設定だった。`.wslconfig` の `networkingMode` が `mirrored` になっていたのが原因だ。

:::message
**`mirrored` と `NAT` って何が違うの？**

ざっくり言うと「WSL2をネットワーク上でどう見せるか」のモードの違いだ。

- **NAT（デフォルト）**：WSL2は専用の仮想ネットワークの中に住んでいて、Windowsが代理人として外と通信する。WSL2自身はWindowsの「奥の部屋」にいるイメージ。外から見ると全部Windowsの住所に見える。
- **mirrored**：WSL2がWindowsと同じネットワーク住所を共有する新しいモード。WindowsとWSL2が"同じ顔"でLANに並ぶので、localhostの共有などが楽になる。便利な反面、まだ新しくて、こういう同一サブネットへの接続でつまずくことがあるらしい。

私の場合、以前パフォーマンス目的で `mirrored` にしていたのが、ここで足を引っ張った。`NAT` に戻したら、あっさり繋がった。
:::

```ini
[wsl2]
networkingMode=NAT
```

変更後は `wsl --shutdown` で一度落として再起動。これで開通した。

### 3. sshdが寝ていた

「Tailscaleは繋がっているのにSSHが通らない」という、いちばん混乱するパターンに陥った。

トンネルは掘れている。なのに玄関のドアが開かない。

調べたらMac mini側でsshd（SSHの受付係）が起動していなかった。macOSはデフォルトでSSHが無効なのだ。受付に誰も座っていなければ、当然ノックしても返事はない。

```bash
sudo lsof -i :22
```

何も出てこなかったので「あ、寝てるな」とわかった。システム設定 → 一般 → 共有 → **リモートログインをON** にして、受付係を叩き起こして解決した。

## なぜTailscaleを選んだか

隔離したMac miniに会いに行く方法は、いくつか候補があった。それぞれ見送った理由つきで並べる。

|方法|隔離できる？|見送った理由|
|---|---|---|
|静的ルート|◎|メインルーターが非対応だった|
|DMZ|△|セキュリティが下がる（後述）|
|ブリッジモード|✗|そもそも隔離にならない|
|**Tailscale**|◎|無料・簡単・暗号化済み。文句なし|

:::message
**DMZって何？なぜ避けたの？**

DMZ（DeMilitarized Zone＝非武装地帯）は、ルーターの機能の一つで、特定の機器を「ファイアウォールの外側」に近い場所に置いて、外から直接アクセスできるようにする仕組みだ。

外部からアクセスさせたいサーバーを置くのには便利。でも裏を返せば、**その機器がインターネットの荒波に直接さらされる**ということでもある。今回やりたかったのは「外に晒す」の逆、「内側でこっそり隔離する」なので、方向性がまるで逆だった。だから却下。
:::

Tailscaleはインストールして両方でログインするだけで、デバイス間に暗号化されたトンネルが張られる。ファイアウォール越しでも勝手に経路を見つけてくる。

正直、こんなに簡単でいいのかと拍子抜けした。

## できあがった構成

```
[通常時]
隔離部屋 ─X─ メインネットワーク
        姿が見えない

[会いに行くとき]
隔離部屋 ──Tailscale（暗号化）──→ メインネットワーク
```

- 物理的隔離：サブルーターのRTモードで別サブネット
- 通信経路：Tailscaleのトンネルだけ
- 認証：SSH鍵認証

怖かったものが、ちゃんと「壁の向こう」に行ってくれた。しかも、会いたいときはいつでも会える。

---

## やってみてわかったこと

ネットワーク隔離なんて難しそうな響きだが、やることは**ルーターを1台足してサブネットを分ける**だけだった。と言いたいところだが通信は目に見えない水路のようで何が何だか分からず難しすぎるけど少し学べた気がする。

あとはTailscaleが全部いい感じにしてくれる。

詰まった3つも、振り返ればどれも「設定がぶつかっていた」「デフォルトでOFFだった」「受付が寝ていた」という、原因がわかれば一瞬で片付く類のものだった。とはいえ、その一瞬にたどり着くまでが毎回いちばん長い。

今、Mac miniは壁の向こうで静かに動いている。会いに行く道はトンネル一本だけ。

ボットに何かあっても、メインPCへの被害経路がぐっと狭まっている。**攻撃される面が小さくなった安心感**は、実際に壁を立ててみるまで実感できなかった。

得体の知れない同居人を、信頼できる隣人くらいの距離感に引っ越しさせた。そんな気分だ。

AIがいなければ決して到達する事のない領域だけどAIを使うといとも簡単に到達させてくれる。AIの凄まじさを身をもって体感している。
